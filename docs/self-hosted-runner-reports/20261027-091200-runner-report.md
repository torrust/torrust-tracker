## Recommendations

These are proposals. None were applied to the runner by this report.

1. Restore service first. With the maintainer's approval and while no job is running, stop and remove
   the four orphaned containers, then run `systemctl start docker-ci-prune.service` and confirm that
   `docker system df` shows the build cache falling toward 120 GiB. If the cache stays pinned,
   investigate the 121 Active snapshots before any broader prune.
2. Find out why the containers were orphaned and make cleanup survive a cancelled run, for example a
   cleanup step with `if: always()` plus a label so a janitor can remove stale containers.
3. Add a prune for stale labelled containers to the daily service, and decide a cleanup for the host
   Cargo target cache.
4. Add a disk alert (for example a check that notifies above 85% of `/`) and record the bytes freed
   by each prune.
5. Revisit the setup guide's statement that the disk "is sized to absorb" the cache, because the
   cache reached 253.6 GB.
6. Schedule the pending reboot after the runner is idle.

Each item needs a GitHub issue before work starts. Items 1 to 5 are tracked in
[issue 2673](https://github.com/torrust/torrust-tracker/issues/2673); its specification is in the
spec-only pull request [2674](https://github.com/torrust/torrust-tracker/pull/2674). Item 6 (the
pending reboot) has no issue yet.
