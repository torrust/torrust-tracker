Reading the two 0 B runs: this is the pattern the earlier reports named as a warning (a prune that frees 0 B while the cache is far above target), so it was checked. The disk was at 53% after both runs, below the 70% restart threshold, and sysstat shows the runner nearly idle on 2026-11-01 and 2026-11-02 (99.6% idle, no jobs), so no new cache was created that could be freed. The cache is not stuck now (see Disk Space). The cache size at 04:00 on those two days was not recorded, so the explanation that the cache was already below the target is a hypothesis, supported by the idle days and the 53% disk usage, not proven.

What is verified and what is not:

- Verified: seven consecutive scheduled runs under systemd succeeded and left the disk at 51% to 53%; none needed the restart.
- Not verified: the restart triggered by the real 70% threshold under systemd. It never fired, because the disk never reached that level after a prune. The restart branch itself was tested on the runner with a lowered threshold on 2026-10-27, and the failure exit at 85% was tested only with stubs.
- The trigger that leaves orphaned build state in dockerd is still unproven.

## Recommendations

1. Ask the maintainer whether to schedule the pending reboot while the runner is idle (F2).
2. Ask the maintainer whether to remove `festive_cerf` and whether to look into the cancelled-step hypothesis for leftover containers (F3). This is a separate topic from the build-cache issue, because a running container did not stop the prune. No issue exists yet; a recommendation without an issue is a draft.
3. Re-measure the host Cargo target cache in the next report to see whether growth continues (F4).
4. Take the next report on a fixed cadence, and when a deployment of the script is needed, copy it from the repository (`docker-ci-prune.sh`) as the guide describes.
5. Alerting and prevention proposals stay in `docs/issues/open/2673-runner-disk-full-build-cache-not-pruned/deferred-proposals.md`; the evidence here does not call for implementing any of them.
