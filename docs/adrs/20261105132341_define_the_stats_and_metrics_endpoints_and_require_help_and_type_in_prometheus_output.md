# Define the stats and metrics endpoints and require HELP and TYPE in Prometheus output

## Scope

This is a repository-level decision. The two endpoints are served by `axum-rest-api-server`, the
Prometheus exposition text of `/metrics` comes from the `torrust-metrics` crate, and the rule on
Prometheus output applies to every package that exports it. It is therefore recorded in
`docs/adrs/`.

## Description

REST API v1 has two statistics endpoints that look alike and have caused confusion:

- `GET /api/v1/stats` returns the global tracker statistics as one flat resource (`Stats`), in JSON or
  in a hand-built Prometheus text of `name value` lines.
- `GET /api/v1/metrics` returns the extendable labelled metrics of all subsystems
  (`LabeledStats`), in JSON or in the exposition text generated by `torrust-metrics`.

Readers have asked whether `/stats` is the deprecated predecessor of `/metrics`, and whether the
legacy Prometheus text of `/stats` is supposed to look like the real exposition format. The git
history answers both: `/metrics` was added next to `/stats` by the merge of PR #1414 ("New API
endpoint with extendable metrics") as a new endpoint, with no deprecation. Later the global values
of `/stats` were calculated from the labelled metrics ("Global metrics in API loaded from labeled
metrics", #1581), which made the aggregated view a summary of the labelled one, not a legacy copy.
The only deprecated items are the `completed` field and the
`tracker_core_persistent_torrents_downloads_total` metric (see the ADR "Define completed-download
metric retention names").

The text of `/stats?format=prometheus` has no `# HELP` and no `# TYPE` lines. The Prometheus text
format makes both optional, so a server scrapes it, but a metric without `# TYPE` is `untyped` and
the lint of `promtool check metrics` warns about the missing help. Issue #2719 fixed the parts that
broke scrapers (a boolean value and the missing final line feed) and left the metadata open.

## Agreement

1. **`/stats` is not deprecated.** It is the supported endpoint for the aggregated, unlabelled
   tracker statistics: a fixed, flat set of global values for dashboards, scripts and quick checks.
   Only the individual items named above are deprecated. Deprecating or removing the endpoint needs
   a new decision.
2. **`/metrics` is the supported endpoint for the extendable labelled metrics.** New metrics, new
   labels and per-subsystem series belong there, not in `/stats`. `/stats` has a fixed set of fields
   that changes only by a compatible, additive change of the v1 resource.
3. **Both endpoints keep both formats.** `format=json` is the structured form and
   `format=prometheus` is the form for Prometheus scrapers, on each endpoint.
4. **Every Prometheus text this tracker exports must carry `# HELP` and `# TYPE` for each metric
   family, on every endpoint.** A metric without them is a defect, even if Prometheus accepts it.
   The type is the real Prometheus type of the value (`counter` or `gauge`), and the help is a
   one-line description that is written once and shared with the other formats, not copied by hand
   into each renderer.
5. **The legacy text of `/stats?format=prometheus` does not yet follow rule 4.** It prints numeric
   values only, as fixed by #2719. Adding `# HELP` and `# TYPE` to it is a follow-up issue. Metric
   names of the legacy text do not change, because they are part of API v1; the types are chosen
   for the existing names (a counter keeps its name even when it has no `_total` suffix).

## Alternatives Considered

- **Treat `/stats` as deprecated in favour of `/metrics`.** Rejected: no decision or commit says so,
  `/metrics` is labelled and per-subsystem and is not a drop-in replacement for the aggregated
  resource, and consumers use `/stats` today.
- **Allow Prometheus text without `# HELP` and `# TYPE`.** Rejected: it is valid, but it drops the
  type, which tools use to pick `rate()` for counters and the right panel for gauges, and it leaves
  the meaning of a value to a source file. The text is the contract between the tracker and its
  operators, so it documents itself.

## Consequences

Contributors who touch either endpoint know what each one is for and do not need to re-derive its
status from the history. New Prometheus output must ship with help and type. Until the follow-up
issue lands, `/stats?format=prometheus` is a known exception, recorded here and in the module docs.
