## Priority Conclusions

- No confirmed exploitable vulnerability was identified.
- Native zlib reachability is a `p2` investigation. Escalate to `p1` if an affected API is
  reachable from attacker-controlled runtime input.
- Explicit workflow permissions are `p3` hardening under the current read-only repository token
  default. Release and CI jobs are split because their trust boundaries and verification differ.
- Non-affecting findings receive no remediation priority and remain in the catalog with recheck
  triggers.
